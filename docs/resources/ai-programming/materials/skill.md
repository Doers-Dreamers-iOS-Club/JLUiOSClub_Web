# 小游戏体验检查

先读取项目中的玩法约定和运行说明，结合用户指定的版本、地址与检查重点安排体验。缺少运行地址或规则时，先从项目说明寻找；仍不明确再询问。

## 检查方法

围绕当前已有功能，选择能区分不同状态的操作：首次开始、正常操作、暂停与恢复、结束与重开。对用户本次修改过的功能，比较修改目标与实际表现，并检查相关的原有行为。

有浏览器工具时，先读取页面结构，再定位控件并操作。以工具的实际返回记录结果。游戏画布内的实时表现，可结合截图、日志或用户试玩反馈。需要通过脚本检查时，依据项目的实际环境选择执行方式。

本轮任务是检查与建议；用户要求修复后，再根据问题安排修改。

## 问题记录

每项问题写明：
- 发生条件与最短操作步骤。
- 依据玩法约定得到的预期结果。
- 实际观察到的结果，以及截图、日志或相关位置。
- 对玩法的影响和建议下一步。

把观察与原因推断分开。按阻断玩法、影响体验、可选改进排序；相同根因合并描述。

## 交付

用简短文字说明本轮检查的场景与结果，给出优先问题。尚需用户试玩或其他条件确认的部分，列出具体检查动作。最后建议下一轮只推进一项最有价值的改动。
