# 常用操作：卡在某一步时来查

[回到阅读入口](/resources/ai-programming/)

## 开始前确认当前项目

> 请先确认当前工作的项目目录，查看文件，说明运行方式，并找到与【本次目标】相关的实现。先讨论方案。

适合拿到现成项目、换会话或隔几天继续时使用。随后检查它说的目录与文件是否对应当前版本。

## 想法还不清楚

> 我想为【谁】解决【场景中的问题】。请围绕第一版问几个会影响实现的问题，帮我把流程和完成条件整理出来。

回答之后，把已经作出的决定留下来，作为后续修改的共同起点。

## 开始一轮修改

> 当前行为是【现状】，希望变成【目标】。保留【已有行为】。请先列出影响位置和检查方法，再实现这一项。

改动完成后看差异，实际运行，反馈具体结果。

## 为了继续改，需要先学一点

> 请沿【一次具体操作】解释实际执行顺序，标出相关位置。我想判断【问题】，先讲清影响这个判断的关系，再给一个可以验证的预测题。

解释之后自己作预测，再用代码或运行确认。

## 运行不符合预期

> 环境是【系统、工具、浏览器】。按【最短步骤】操作，实际出现【结果】，预期是【结果】。相关报错为【文本】。已经试过【方法与结果】。请先调查原因。

## 这一轮走偏了

> 先停一下。本次目标仍是【目标】，暂时先处理【范围】。请总结已经修改的部分，重新安排下一步。

## 准备换会话

> 请把当前目标、决定、运行方式、相关文件、已完成工作、现存问题与下一步整理成项目记录。

保存到项目中，下次先读记录和相关文件，再开始修改。

## 使用 Skill

先在当前工具中确认技能可见，再明确选择它，补充本次对象、输入和重点。ZCode 中可以用 `$` 选择技能。

## 使用 MCP

先确认服务在线和工具列表，再做一个最小调用；之后带回真实任务。反馈中保留工具返回的错误文本。

## 接入 API

先在 DSH 等工具里选择内置提供商，填入自己的密钥并保存，选择模型后新建对话、发送一条消息。连接走通后，再认识服务地址、模型名、协议和用量；具体步骤见 [DSH 接入说明](/resources/ai-programming/chapters/api-setup)。
