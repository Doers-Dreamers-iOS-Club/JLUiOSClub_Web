# 从想法到作品：可操作图解与插画叙事设计

状态：已完成全部章节图解与小动画，规格审查、代码审查及生产构建回归通过。

用户选择：可操作图解、插画叙事，以及讲解过程的小动画。最新调整：新增插画和动画用于章节正文，首页不新增插画叙事。沿用上轮专题架构、现有内容和网站视觉。

## 设计依据

应用 brainstorming 与 awesome-design-md 技能。查阅了后者本地索引及 Notion、Figma、Mintlify、Apple 条目；这些本地条目只有摘要或外链，不是完整品牌设计规范。这里只参考索引中编辑式布局、阅读优先、画布操作与留白的方向，具体字体、颜色、间距和动效仍以本仓库主题令牌为准。

三个候选方向：

| 方向 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| 可操作图解 + 插画叙事 | 让学习者改变条件、观察因果，兼顾阅读 | 每幅图需要具体模型和解释 | 采用，符合用户选择 |
| 闯关式练习 | 任务明确，适合集中练习 | 通关节奏容易打断长文 | 保留现有章节小题，不新增通关门槛 |
| 滚动驱动插画 | 顺着文章讲故事，视觉连续 | 容易只观看而没有主动判断 | 使用手动翻页分镜，滚动只负责轻微入场 |

## 统一视觉与阅读节奏

继续使用白色纸面、深灰文字、蓝色操作强调、衬线标题与细规则线。插画以文件页、便签、浏览器窗口、线缆、时间轴为基本对象，圆角和阴影来自现有令牌；不换品牌色，不加入独立游戏界面。

每幅图分为四个区域：一句问题、可操作画面、操作控件、随着操作改变的观察结果。插画中保留短标签，长解释放在下方。默认静止且有可读画面，点“试试看”后再演示。

桌面画面约 640–720 px 宽；普通图画面高约 300–420 px。手机在 320–430 px 宽度下把双栏改为分屏切换或上下排列，说明和按钮移到画面外，避免把整张桌面图缩小到文字不可读。

每章一幅主图，第三/四章可再配一个小实验。插画紧邻其解释的正文段落出现，不集中到首页或堆在章首。原拟首页的三幕故事拆入对应章节：第一章的需求段落呈现“提出想法”，试玩段落呈现“观察第一版”，第二章反馈段落呈现“带着观察继续修改”。每幕使用同一条蛇和同一张项目纸建立连续性，并与所在章节主图结合，避免重复增加独立大模块。

## 具体交互

### 1. 作品预览盒：把一句想法展开成具体选择

位置：第一章“从一句帮我做一个游戏开始”后，替换该章重复的计时 SnakeLab。

静态画面：左侧需求便签，中间浏览器示意，右侧观察笔记。初始为笼统愿望“做一个贪吃蛇”，三个行为槽尚未明确。

玩法：依次选择“点击开始 / 打开就运行”“撞墙结束 / 穿过边界”“重开清零 / 保留分数”。每次选择只改变对应画面与需求句子。选择完成可切换到“本讲义第一版约定”，对照差别。

反馈：具体描述变化，例如“你选择点击开始，打开页面时蛇保持静止”。用动作前后两帧展示差异，支持重播。

教学目标：同一个项目名字包含许多未明确的行为；写需求是在作出选择。

边界：预设规则的教学示意，不宣称在实时调用 AI 生成作品。展示第一版约定时完全匹配原文。各项选择都有按钮，拖拽不作为必需操作。

### 2. 上下文桌面：文件放在那里，Agent 就知道了吗？

位置：第二章“PS 2：上下文”附近，六轮 Prompt 组件继续保留。

静态画面：左边是项目文件夹，中间是本轮对话托盘，右边是“现在能依据什么判断”的观察窗。

玩法：点选“项目路径”“入口代码”“旧聊天”“当前玩法决定”“实际报错”，将信息卡片加入本轮上下文；再次点击可移除。桌面支持拖动作为补充操作。

反馈：路径卡只显示位置线索，代码卡揭开实际实现，需求卡明确预期，报错卡提供现象。缺信息时显示“还需要确认什么”，不编造模型的成功概率。

叙事：第一幕只给路径，第二幕读取代码，第三幕补充玩法决定。每幕下方生成一句示例任务，可复制。

教学目标：文件在磁盘上与本轮实际读到内容是不同关系；按当前问题补充信息。

边界：抽象示意，不声称复刻某款 Agent 的内部上下文或 token 用量。不把所有资料加入作为最优答案。

### 3. 暂停剖面图：按钮背后发生了什么？

位置：第三章四种状态表后，升级此章 SnakeLab；第一章不再展示同一计时器。

画面：上方是可操作的小棋盘，下方展开三层：当前局面、移动触发器、状态节点。初始“待开始”，点击开始后到“运行中”。

操作：开始、暂停、继续、触发示例结束、重新开始。选中状态节点可查看解释，不改变实际状态；实际变化只能由操作按钮触发，避免把不合法跳转当作真实规则。

反馈：暂停冻结棋盘位置，触发器停止但状态数据保留；继续从原位移动；重开清除旧局面并开新局；已结束不能继续。无效操作按钮禁用并说明原因。

单步模式：每次点击只推进一次移动，适配减少动态效果。教学示意保留一份可见状态快照，便于比较“暂停”和“结束”都不动却不同。

目标：把原文状态表变成能观察的因果模型。

### 4. 计时器显微镜：为什么重开几次就越跑越快？

位置：第四章“先调查，再决定改哪里”附近，替换 debug 类型的纯步骤流程图；排错步骤以紧凑说明保留。

画面：正确实现与故障实现并排，同一固定步进时间轴，下面显示活动计时器数与蛇的位置。

操作：两边同步开始；每次点“重开”推进一个事件。正确侧清理旧循环并只保留一个，故障侧模拟旧循环残留。点“清理旧循环”切换到修复后的模型，再重复同样操作。

反馈：以脉冲点表示移动触发，显示 1、2、3 个模拟计时器如何在同一时间窗口产生多次更新；同时给出事件记录。

边界：明确“示意一种可能原因”；不能暗示所有游戏加速都由此导致。不真的创建无限累积的定时器，以一个时钟驱动有限数量的模拟脉冲，最多显示三个。重置还原两侧状态。

### 5. 版本翻页册：这一版究竟改了哪里？

位置：第四章版本保存之后，作为可展开的小图。

画面：三张项目快照卡，分别代表初版、速度选择、暂停功能。每张包含缩略画面、少量代码差异和验证记录。

操作：选择两版，拖动比较滑杆或点击“前一版 / 后一版”。切换“画面”“代码”“记录”三个视角。手机用切换按钮替代双栏。

反馈：只突出当前版本真实差异，新增代码与对应控件用同一条引线关联。点击“模拟回到这一版”更新示意预览，并显示实际项目恢复前需要确认哪些改动会被放弃。

边界：使用预置版本数据，只改变网页演示；不会操作用户仓库。界面区分“比较版本”“模拟恢复”，不把恢复描述为绝无代价。

### 6. Skill 配方桌：什么应该写进技能？

位置：第五章“通用指令、快捷命令与 Skill 怎样分工”后，替换 skill 类型的纯步骤图。

画面：三叠纸分别是“项目事实”“本次任务”“可复用方法”，下方是工具抽屉。起始有六张待整理卡。

操作：选择卡片后指定归类，也可拖动。示例包括“入口是 index.html”“这次只检查暂停”“先列预期，再记录实际”“浏览器工具提供点击能力”等。工具能力单独放在工具层。Skill 中可以写“打开浏览器”这类步骤，但写下步骤不等于拥有对应能力。

反馈：每张卡进入位置后解释原因；允许移回，点击“看一个整理好的例子”显示完整组织方式。点“带到另一个项目”替换项目事实，保留通用方法，说明适用范围仍需判断。

教学目标：方法、事实、当前目标与实际操作能力彼此配合；可复用方法运行时仍需读当前项目。

### 7. MCP 接线台：把方法接到真正的操作

位置：第六章连接说明附近，升级现有 MCP 图为可操作场景；保留 Host/Client 到 Server 的协议关系。

画面：任务便签、Agent 所在应用、MCP 服务、浏览器和本地网页。蓝色小点代表调用，空心点代表返回结果；线条表示实际关系。

操作：按“接入服务”“启动本地网页”“执行检查”三步操作；可切换“服务未连接”“网页未启动”“全部就绪”预设情境。点开节点看当前输入与输出。

反馈：服务未连接，工具调用无法发出；服务连接正常但本地网页未启动，浏览器工具返回页面不可达；全部就绪，演示点击开始/暂停并返回观察。线路沿出错层突出，避免把所有错误都归为 MCP 问题。

边界：只演示预置状态，不连接真实本地服务或访问用户浏览器。画面标记“连接过程示意”。练习只需点选，无须精确拖拽接线。

### 8. API 信封：一条消息怎样往返？

位置：API 补充教程字段表后，升级现有 API 图。

画面：客户端将问题装入信封，封面是服务地址、认证占位符与模型，内部是请求内容。信封到达服务后展开响应。

操作：点击字段翻开解释；选择“正常配置”“认证失败”“模型不匹配”三个预设，点“发送示例”。成功时可切换完整展示与分段展示。

反馈：失败标记落在对应环节，解释先检查什么；成功显示请求/响应两个抽屉，突出消息如何变成返回内容。

边界：固定虚构凭证，不接受真实密钥，不发送网络请求；返回内容明确为预设。分段显示不声称一个字等于一个 token；错误文案标为示意，不编造通用状态码。

## 章节小动画

小动画是本轮设计的一部分，附着于对应图解和正文情境。每个动画聚焦一个变化，通常持续 2–6 秒，读者主动播放后停在可观察的结果，支持重播。交互状态模型负责实际变化，动画只表达过程，避免动画结束回调成为逻辑正确性的前提。

| 所属内容 | 动画表现 | 读者能观察到什么 |
| --- | --- | --- |
| 第一章：想法到第一版 | 需求便签展开为几条规则，规则依次连到浏览器中的对应控件 | 一项具体要求怎样对应一个可检查的行为 |
| 第二章：本轮上下文 | 点选信息卡后，卡片移入对话托盘，观察窗同步补齐信息 | 路径只是线索，读入的内容才提供事实 |
| 第三章：暂停与继续 | 移动脉冲停止，蛇身位置与状态快照保留；继续后脉冲恢复 | 停止更新不等于清空本局数据 |
| 第四章：重复计时器 | 每次模拟重开后，故障侧增加一条脉冲轨道；修复后多余轨道消退 | 重复更新如何改变移动节奏 |
| 第四章：版本比较 | 切换快照时变更行短暂强调，引线连接到变化的界面元素 | 代码差异与可见结果之间的对应关系 |
| 第五章：Skill 复用 | 方法卡保留，项目事实卡替换，再展开新项目的检查记录 | 复用的是方法，事实仍需重新读取 |
| 第六章：MCP 调用 | 实心调用点依次经过相关节点，空心结果点沿返回路径回到 Agent | 调用与结果的方向，以及故障停在哪一层 |
| API 补充：请求与响应 | 请求信封展开字段并发送，响应信封返回；预设失败在对应环节停止 | 配置字段与一次信息交换的关系 |

普通按钮与图层过渡保持短促；持续计时的图解仍按实验控件运行，可随时暂停。减少动态效果时，以状态切换、静态引线和逐步高亮替代位移。离屏、切页和浏览器标签隐藏后停止播放。移动端用同样的状态变化表达，不依赖悬停。不会为正文添加持续漂浮、自动循环或滚动劫持。

## 章节中的插画组织

首页保持现有导读布局，本轮不新增首页插画、分镜或封面交互；此前已有的静态封面保持现状。新增插画全部服务于章节正文的具体情境。每幅图设置稳定锚点，正文可以直接引用；相关段落先提出问题，图解让读者操作和观察，后文再解释并回到实际项目。

不额外设置全屏游戏大厅。原有阅读标记仍由读者主动操作，完成演示不自动标记整章读完。现有知识小题保持独立。

## 实施优先级

建议首先完成四个最能体现差异的章节主图：作品预览盒、暂停剖面图、计时器显微镜、MCP 接线台；插画分镜融入对应章节主图与段落，不单独改造首页。

随后补充上下文桌面、版本翻页册、Skill 配方桌与 API 信封。完整方案是八种互动内容，不把现有流程图和新图重复堆在同一段。

## 交互统一规则与技术边界

- 每幅图显示“试试这个操作”的具体引导、当前状态、一键重置和观察结论。
- 动画用于解释状态变化，按钮/图层变化约 180–300 ms，物体往返约 500–900 ms；提供暂停和单步，不自动循环。
- 控件至少 44 px；按钮、滑杆均有键盘路径，拖拽提供点选替代。
- 暗色模式复用全站令牌；图形填充、文本、连线分别适配，对比度不依赖颜色唯一表达。
- 默认 SSR 输出静态图和摘要；交互初始化失败仍可读。离屏、切页、切换浏览器标签后停止演示，减少动态效果时用分帧切换。
- 新组件使用 SVG + Vue 的可控状态，无需引入重量级图形框架。主图各自独立；共用外框、图例、控制条和播放生命周期。按章节加载，连续阅读版按进入视口再初始化运行逻辑。
- 预设状态、插画元素与可见解释来自同一数据模型，避免文案与图形不同步。现有正文仍以 _content 片段维护。

## 验收标准

每幅图都能回答：读者改变了什么、画面发生了什么变化、因此理解了什么。检查正确和错误路径、反复重置、非法状态、键盘操作、320 px 手机、暗色与减少动态效果；验证离屏与换页停止计时。主线速度规则继续是轻松/标准、开局前选择、重开保留选择。功能说明以讲义为准，不把演示简化当成真实工具实现。
